## Счета Amazon Ads и регуляторный сбор (с 16.10.2026)

Расход из Ads API (`cost` в отчётах SP/SB/SD) — **без НДС и без регуляторного сбора**: сверка 16.10.2026 по
цепочке из 24 счетов ES за 02.08–29.09 — реклама в счетах 11 590 €, расход API 11 661 € (+0,6 %, граница
счетов). Сбор и НДС Amazon добавляет только в счёте. Поэтому ни Кабинет, ни витрина Power BI сбора не видят.

- **Источник — Billing API**, `GET /invoices` (заголовок `Accept: application/json`; `vnd.invoices.v1.1+json`
  отвечает 406), отдельно по каждому профилю (`Amazon-Advertising-API-Scope`). Профилей девять (ES, DE, FR, IT,
  NL, BE, PL, SE, UK), счета есть у шести: ES с 10.12.2024, IT и FR с февраля 2025, UK март–май 2025, BE
  январь–июнь 2026, DE с 19.03.2026. Счёт выставляется по ПОРОГУ (~500 €), а не по месяцу: период одного счёта —
  от дня до месяца, соседние счета делят граничный день.
- **`amountDue` — БЕЗ НДС, и сбор уже внутри**: реклама счёта = `amountDue − Σ fees`. НДС — `taxAmountDue`:
  у ES 21 %, у IT, FR, DE ноль (другой счёт-фактура). Набирающийся счёт (`ACCUMULATING`) номера не имеет.
- **Сбор считается по стране ПОКАЗА**, а не по профилю: строки `REGULATORY_ADVERTISING_FEE` с `countryCode`.
  ES, IT, FR — около 3 % рекламы своей страны; у профиля DE платится только за показы в Австрии (AT) — 0,6 %
  от расхода; копеечные строки других стран бывают в любом счёте. Ставка от счёта к счёту стабильна
  (ES 2,8–2,95 %), поэтому за дни без счёта сбор можно оценивать ставкой профиля.
- **Загрузчик** — `Kabinet - Amazon Ads Invoices` (`nb/ads_invoices_loader.py`, 08:50 Kyiv): каждый прогон
  перечитывает всю историю API (сотни счетов, секунды) и MERGE в `dnipro_m.raw_amazon_ads_invoices` и
  `raw_amazon_ads_invoice_fees`; набирающиеся счета заменяются целиком. Ссылки на PDF (`downloadableDocuments`)
  не храним. `dry_run=1` — без записи, печатает сбор по месяцам (сбор счёта разнесён по дням его периода
  пропорционально расходу API). Сбор за август–сентябрь 2026 — ≈ 472 € (2,56 % рекламы Amazon), за всю историю
  4 492 € и 6 £ (UK). В маржу Кабинета он пока НЕ входит — как добавлять (в витрину Power BI или отдельной строкой в
  Кабинете), решает владелец.
- **Дневной вид для аналитика** — `dnipro_m.dnipro_m.v_amazon_ads_fees_daily` (`sql/v_amazon_ads_fees_daily_2026-10-16.sql`):
  день × страна профиля × страна показа × тип сбора. Сбор счёта разнесён по дням его периода пропорционально расходу из
  Ads API (`allocation = by_ads_spend`), до 06.02.2026 таблиц кампаний нет — поровну (`even_by_days`). Сумма по счёту
  равна сбору счёта до цента. Валюта — профиля.
- **SB без товара** (кампании без ASIN в названии и без покупок, разнос аналитика их не раскладывает) — та же
  дыра в марже: ES март 126 €, апрель 652 €, май 195 €, сентябрь 44 € («Birthday Sale-SB-PC»), остальные рынки
  ноль. Реклама в витрине Power BI по IT, DE, FR сходится с API до цента, по ES меньше ровно на эти суммы.

## Отчёты Amazon Ads: поисковые запросы, таргетинг, плейсменты, невалидный трафик (с 16.10.2026)

**Amazon хранит эти отчёты недолго, и окно сдвигается каждый день** — проверено 16.10.2026, дату начала хранения API
называет сам в ответе на слишком старую дату («must be equal to or after report type data retention start date»):
SP (`spTargeting`, `spCampaigns` с плейсментом, `spSearchTerm`) — 95 дней, SB поисковые запросы (`sbSearchTerm`) —
60 дней, невалидный трафик (`spGrossAndInvalids`, `sbGrossAndInvalids`) — 365 дней. Что не забрали вовремя, потеряно
навсегда; поэтому загрузчик с первого прогона берёт всё, что ещё отдаётся.

- **Загрузчик** — `Kabinet - Amazon Ads Reports` (`nb/ads_reports_loader.py`, 07:10 Kyiv), Ads Reporting v3, квоту
  createReport SP-API не трогает. Пишет сырьё в `dnipro_m`: `raw_amazon_ads_sp_targeting`, `raw_amazon_ads_sp_placement`,
  `raw_amazon_ads_sp_search_term`, `raw_amazon_ads_sb_search_term`, `raw_amazon_ads_gross_invalid` (SP и SB вместе,
  колонка `ad_product`). У каждой строки `profile_id`, `country`, `currency` (валюта профиля, GB/SE/PL не в евро).
- **Окно**: таблица по профилю пуста — от даты начала хранения; иначе — последние `reorder_params.ads_reports_reread_days`
  (30: атрибуция продаж закрывается за 14 дней) и всё, чего ещё нет. Окно профиля заменяется атомарно (`replaceWhere`):
  дублей нет, строки, которых Amazon больше не отдаёт, уходят. Группа «профиль × отчёт», у которой упал хоть один
  кусок (по 31 дню), не пишется вовсе — остаётся прежняя; прогон падает после пульса.
- **Профили** — только с рекламой: есть счёт Amazon Ads (`raw_amazon_ads_invoices`) за 400 дней. На 16.10 это ES, IT,
  FR, DE, BE; новый рынок с рекламой подхватится сам, когда по нему придёт первый счёт.
- **Объём** (проба 16.10, два дня): ES в день — таргетинг ~90 строк, плейсменты ~85, поисковые запросы SP ~65, SB ~25,
  невалидный трафик ~50; IT — в 2–4 раза меньше, DE и FR — единицы. Первая загрузка — около 190 отчётов, их Amazon
  собирает минутами; таймаут джобы 4 часа.
- **Поисковые запросы SP на деле хранятся ~65 дней, а не 95**, хотя API называет датой начала хранения 13.07.2026 и
  запрос с неё принимает. Первая загрузка 16.10.2026: отчёты за 13.07–11.08 пришли пустыми у всех профилей, строки
  есть с 12.08 (ES, IT; таргетинг и плейсменты SP за те же дни — полные, с 13.07). Значит, на пропуск загрузчика у
  поисковых запросов SP запас около двух месяцев, а не трёх. У SB поисковые запросы — 60 дней, как и заявлено.

## Раздел «Реклама»: реплики и что будет на экране (с 18.10.2026, решения владельца)

Экран Кабинета читает только Lakebase, а отчёты рекламы, счета и сборы лежат в Unity Catalog, поэтому сначала реплики
(`Kabinet - Ads Replica`, `nb/ads_replica.py`, 10:20 Kyiv, `sql/ads_replica_2026-10-18.sql`), потом экран. Таблицы в
`kabinet_data`: `ads_campaign_daily` (кампания × день: SP — сумма по плейсментам нашего отчёта, SB и SD — таблицы
кампаний аналитика `raw_amazon_ads_{sb,sd}_campaign_<рынок>`), `ads_search_term_daily` (SP и SB, 35 дней),
`ads_placement_daily`, `ads_invalid_traffic_daily`, `ads_fees_daily` (сбор по дням), `ads_invoices` (сумма без НДС со
сбором и НДС). Окно `ads_replica_days` (120) заменяется целиком одной транзакцией; суммы — в валюте профиля, в евро
переводит страница через `to_eur`; Британия — GB (у профиля рекламы она UK, у таблиц аналитика — суффикс `uk`).

- **Расход сходится со Spend Кабинета** (сверка 18.10.2026): SP нашего отчёта + SB аналитика = Spend до цента на IT
  август и сентябрь, DE август, FR сентябрь; ES август +0,73 €. Расхождение одно и известное: SB-кампании без товара
  (ES сентябрь «Birthday Sale-SB-PC», 44 €) в Spend Power BI не попадают — в реплике они есть, экран показывает их
  отдельной строкой. История SP — с 13.07.2026 (Amazon хранит 95 дней), SB и SD — глубже, из таблиц аналитика.
- **Реальная стоимость** = расход + регуляторный сбор (~2,9 % в ES и IT, <1 % в DE — только показы в Австрии) + НДС из
  счетов (21 % только у ES, IT/FR/DE — 0, обратное начисление). НДС показываем отдельно, «к вычету», в маржу не входит.
- **Пустые траты — главной цифрой запросы с 10+ кликами и 0 заказов** (сумма и список), а не общая доля расхода без
  заказов: ES за 30 дней это 46 % (1 466 € из 3 193 €), но большинство таких запросов — 1–2 клика, и общая цифра пугает,
  не подсказывая, что делать. Общая доля — мелко, с этим пояснением. **Кнопки «в минус-слова» нет** — решение владельца.
