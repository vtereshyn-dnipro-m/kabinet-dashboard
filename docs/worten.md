# Worten Marketplace (с 28.10.2026)

Решение владельца 28.10.2026: подключить Worten по API «тем же путём, что TikTok», **только чтение**. Worten — площадка
на Mirakl (как Leroy Merlin и Carrefour): Mirakl Seller API, магазин DNIPRO-M, `shop_id` 18499, канал `WRT_PT_ONLINE`
(Португалия). Адрес API — `https://marketplace.worten.pt`, не секрет (константа ноутбука).

## Что есть

- `nb/worten_client.py` — клиент: белый список, ключ в заголовке `Authorization`, 429 по `Retry-After`, постранично
  `max`/`offset`, ошибки без ключа и без URL. Тесты — `tests/test_worten_client.py`.
- `nb/worten_rows.py` — строки сырья из ответов API (чистые функции). Тесты — `tests/test_worten_rows.py`.
- `nb/worten_loader.py` — ноутбук `Kabinet - Worten Loader`: офферы и заказы в `dnipro_m.worten.raw_*`, реплики
  `kabinet_data.raw_worten_*` для страниц, пульс последним. Джоба — `nb/jobs/worten_2026-10-28/`, 07:20 и 15:20 Киев,
  под `kabinet-jobs-sp`.
- SQL: `sql/worten_uc_2026-10-28.sql` (Unity Catalog, первым), `sql/worten_2026-10-28.sql` (Lakebase) и
  `sql/worten_rules_2026-10-28.sql` (правило сторожа и свежести — после первого прогона джобы).

## Только чтение: белый список

Клиент отказывает до запроса во всём, чего нет в `ALLOWED`: только `GET /api/account` (A01), `GET /api/offers` (OF21),
`GET /api/orders` (OR11). Принять заказ (OR21), трекинг, правка офферов и цен — запрещены. Новый путь — правкой
`ALLOWED` по «мержи», и только на чтение.

## Секрет — скоуп `worten`

Ключ `api-key` — вносит владелец (28.10.2026); `kabinet-jobs-sp` — READ на скоуп. Значение агент не читает и не
выводит. У Mirakl ключ — в заголовке `Authorization` без «Bearer». Магазин и глубина истории — в `reorder_params`
(`worten_shop_id`, `worten_history_days`, `worten_order_overlap_days`, `worten_window_days`), не в секрете.

## Проба 28.10.2026 (только чтение, A01 / OF21 / OR11)

- Магазин 18499 найден, версия Mirakl 3.1320.
- Офферов 139. Цена задана по каналам (`all_prices`): верхнее `price` — цена без канала, покупатель видит цену канала
  `WRT_PT_ONLINE`. Пример: 41324000 — 39,00 без канала и 31,99 в канале по скидке 20.10–16.11.2026 по Лиссабону
  (в API — 19.10 23:00Z – 16.11 23:59:59Z). Поэтому цена для
  покупателя в сырье — цена канала, со скидкой только при действующем сроке (как в паритете Leroy Merlin, T-37).
- Заказов за 200 суток — один: 65,99 €, комиссия 9,90 €, налог 12,34 € (23 %).

## Данные покупателя в сырьё не попадают

`raw_json` собирается по белому списку полей (`ORDER_KEEP`, `LINE_KEEP` в `nb/worten_rows.py`). Не попадают: имя,
фамилия, `customer_id`, адреса (улица, город, телефон, компания), email уведомлений, трек-номер и ссылка, картинки. Из
адреса доставки — только индекс и страна (география продаж), как у TikTok.

## Загрузка

- Офферы — снимок целиком на каждом прогоне, MERGE по `(shop_id, offer_id)`. Пропавший из ответа оффер не удаляется:
  у него остаётся старый `loaded_at`, а реплика ставит `in_last_load = false`.
- Заказы — по дате изменения (`start_update_date` / `end_update_date`), кусками `worten_window_days` (30 суток). Первый
  прогон — `worten_history_days` (200) назад (решение владельца 28.10.2026), дальше — от отметки последнего целиком
  записанного куска (`dnipro_m.worten.sync_state`) минус `worten_order_overlap_days` (3): статусы меняются задним
  числом. `full=1` — перечитать всю глубину. `dry_run=1` — без записи и без пульса.

## Время

**День заказа Worten — по Лиссабону, а не по Мадриду** (решение владельца 28.10.2026): Worten — Португалия. Приём —
тот же, что у сырья Mirakl (`docs/madrid-time.md`), меняется только пояс: рабочие колонки `created_at`, `updated_at`,
`shipped_at`, `received_at` — часы Лиссабона (`Europe/Lisbon`: летом +1, зимой 0), записанные как UTC (`DATE(x)` сразу
даёт день Лиссабона); `<колонка>_utc` — исходный момент из API, длительности — только по ним. Это отступление от правила
«часы Мадрида» для Leroy Merlin и Carrefour: Лиссабон на час позади Мадрида, и заказ в 23:30 по Лиссабону остаётся в
своём дне. Сводя Worten с площадками Испании по дням, помнить, что граница дня у него на час позже. Сроки
скидок офферов (`discount_start`, `discount_end`) — настоящий UTC: их сравнивают с текущим моментом. `loaded_at` — UTC,
в реплике — тот же, что в сырье (время снимка), поэтому правило свежести видит упавший OF21.

## Деньги

У Worten (Португалия) суммы — с НДС, в евро. Стандартная ставка — 23 %; пониженные ставки (6 % и 13 %) на наших
категориях не проверены — проверить по заказам, прежде чем считать выручку без НДС (оговорка владельца 28.10.2026).

## Показ в Кабинете (PR3, 29.10.2026)

Решение владельца 28.10.2026 (вечер): Worten — новый источник по API, как TikTok Shop, а не реплика Power BI; Power BI
Кабинет не ждёт. Подпись источника — «Worten API, не Power BI».

- **«Площадки» → вкладка «Worten»** (`worten_tab.py`), без флага, под правом страницы. Заказы периода по дате заказа
  по Лиссабону: строки без отмен, отказов и возвратов (`REFUNDED`, `CANCELED`, `REFUSED` — тот же список, что у Leroy
  Merlin в `v_sales_vat_incl_daily`); продажи с НДС — цена строк без доставки; комиссия Worten по строкам. Офферы —
  снимок последней загрузки: цена для покупателя, обычная цена, скидка и её срок.
- **«Обзор»** — строка Worten в блоке каналов и в таблице стран, из `v_worten_sales_daily`, за флагом
  `worten_overview_enabled` (0 до сверки заказов с кабинетом Worten, включает владелец; администратор видит и при 0).
  В карточки и график по дням не входит (их считает Power BI); пока строка показана, подписи карточек — «все каналы,
  кроме TikTok Shop и Worten», под строками — сколько добавляют каналы из API.
  **Когда Worten есть и в витрине Power BI** (PR #407, 30.10.2026), при флаге = 1 его строки показывает реплика
  (`pbi.py`, `GATED`, PR #408) — в карточках, каналах и странах, канал — по площадке витрины. Строка API тогда
  отступает (`load_worten_sales`), иначе Worten посчитался бы дважды; вместе с ней уходят подписи «кроме … Worten».
  При флаге 0 строки реплики скрыты, администратор видит строку API, как раньше. Флаг — в ключе кеша, ответ флага
  живёт 30 с. Безопасный порядок — выложить #408 до «применяй» #407. Разница счёта при флаге 1: вью API не считает
  продажей `REFUNDED`, витрина считает (возврат — отдельно, днём возврата); у Worten возвратов пока нет.
- **Справочники** — площадка `WRT` «Worten», маркетплейс `WRT-PT` (Португалия, евро, НДС 23 %, `legacy_code` wrt_pt).
  Источники Worten (офферы, заказы) добавлены во вью `v_marketplace_data_status`, иначе WRT-PT сразу стал бы «нет
  данных», и сторож завёл бы `marketplace_no_data`; с ними у WRT-PT обычный статус по данным. Вью принадлежит
  `claude_code_ro`, учётка владельца состоит в роли без INHERIT и SET, поэтому замена вью — отдельным файлом под
  `claude_code_ro`: разовое исключение из решения владельца 26.10.2026 «писать через claude_code_ro нельзя» (решение
  владельца 29.10.2026, после демо).
- **Plan Matrix** справочник не читает: вкладки таблицы — список `TABS` в `nb/plan_matrix_prices.py`, Worten там нет;
  в табы аналитика витрины ничего не пишется. Своя вкладка `avg_Worten_PT` — PR2, после подтверждения аналитика.
- SQL — два файла, ДО выкладки кода, по «применяй», каждый отдельно: сначала `sql/worten_status_view_RO_2026-10-29.sql`
