## Экспорт каталога Amazon ES для Марко

**С 15.10.2026 рынок — параметр `marketplace`** (ES по умолчанию, FR, IT, DE): тот же ноутбук и та же джоба, файлы `amazon_<рынок>_catalog_<дата>.xlsx` и `…_latest.xlsx` в папке `/Volumes/dnipro_m/dnipro_m/kabinet_raw/exports/amazon_<рынок>_catalog/`. Рынок в отчёте листингов ищется по `marketplace_name` («France (FR)», «Italy (IT)»), запросы SP-API — с id рынка. Запуск без параметра даёт прежний испанский файл.

Джоба `Kabinet - Amazon ES Catalog Export` (1023271221032583), запуск вручную, без расписания и пульса. Файл —
`/Volumes/dnipro_m/dnipro_m/kabinet_raw/exports/amazon_es_catalog/`, `…_latest.xlsx` всегда последний. Всё на
английском (решение владельца 06.10.2026). Источник кода — `nb/amazon_es_catalog_export.py`: правка идёт PR'ом, проба —
копией в `_probe` с параметром `probe=1` (полный прогон без замены `latest`), после мержа файл выкладывается в рабочий
ноутбук. Так решено 07.10.2026, когда правку попросили провести через PR, — у ноутбука в Databricks нет ни ревью, ни истории.

**С 07.10.2026 в том же листе все три статуса листинга**, а не только активные (Марко спросил, можно ли выгружать и
неактивные): колонки `Status` (Active / Inactive / Incomplete, как в отчёте листингов) и `Inactive reason` в конце листа —
прежние колонки не сдвинулись. Причина — `issues` из Listings Items 2021-08-01 (`issueLocale=en_US`, «severity: message»),
только у неактивных и незавершённых; нет проблем в ответе — пусто, не додумываем. Сортировка Active → Inactive → Incomplete.
На 07.10: 309 / 278 / 68, причина есть у 258 неактивных и 16 незавершённых. Главная причина неактивности — EPR: Amazon
требует номер ERN (214 строк), дальше «access permissions» (76) и неверные языковые данные (68).
Без EAN 66 строк — это родительские контейнеры вариаций (`…_variants`, `… Parent`) и коды Amazon, у них EAN нет по смыслу.

**Каталог Amazon может отдавать у неактивного варианта ФОТО СОСЕДА по семейству** (разбор 14.10.2026, строка 58614000 /
B0F3DSKYJH, SAB-15DX). Привязка SKU → ASIN была верной (отчёт листингов и Listings Items совпали у всех 655 строк), и
выгрузка честно переписала то, что отдаёт Catalog Items, — но Catalog Items у этого ASIN отдаёт восемь фото SA i120
(48312002 / B0H66F7BS4), а в НАШЕМ листинге (`main_product_image_locator`) лежит своё фото SAB-15DX. Так же у трёх других
неактивных сварочных аппаратов того же семейства (родитель B0GF66GLDL) и в целом у 46 строк из 655 (41 неактивная).
Вдобавок `amazon.es/dp/<ASIN>` неактивного варианта открывает ПОКУПАЕМОГО соседа (`landingAsin` ≠ `currentAsin`): человек,
перешедший по ссылке, видит другой товар — это и было «расходится с живой страницей». Неактивных вариантов семейств 142.

**С 14.10.2026 картинки берутся из НАШЕГО листинга, а не из каталога** (решение владельца): Listings Items,
`main_product_image_locator` и `other_product_image_locator_N` → Main image и PTNN — то, что мы сами загрузили. Каталог —
только если в листинге картинок нет вовсе (на 14.10 — 116 строк, почти все контейнеры вариаций); нет одного главного (4
строки) — главное из каталога. Откуда — колонка `Image source`. Так у неактивного варианта в файле своё фото, а не соседа.
Но в листингах фото часто меньше, чем показывает Amazon (у 123 строк одно вместо 6–9), поэтому — вариант Б владельца:
пустые слоты PT добираются из каталога тем же номером слота, **только если главное фото каталога совпало с нашим**
(`Same`) и только снимками, которых в листинге нет (сравнение по содержимому). Где главное фото другое — только листинг.

Перед сохранением каждая строка сверяется с живыми данными — колонка `Check` в конце листа: ASIN из отчёта листингов
против живого листинга (Listings Items), есть ли ASIN в каталоге, есть ли главное фото в нашем листинге. Пусто — строка
подтвердилась. Нужен Pillow в окружении джобы. Пробный файл (`probe=1` или `limit`) — `TEST_amazon_es_catalog_…xlsx`,
листы «TEST …» и первая строка сводки «TEST FILE».

**Фото по статусу листинга (с 16–17.10.2026, решение владельца, разбор 54477000 и 22539000).** Живая строка —
Active в отчёте листингов И BUYABLE в Listings Items сейчас: фото каталога Amazon, это и есть живая страница; фото
нашего листинга бывает устаревшим вкладом (54477000: в листинге 41XmNeOeSEL, на странице 81vTSoBngGL). «Active» в
отчёте без BUYABLE живой не считается: 22539000 (RH-12) там Active, а в Listings Items только DISCOVERABLE, и каталог
отдавал ему главное фото перфоратора BH-20 из того же семейства. Остальные строки — ТОЛЬКО фото нашего листинга, все
слоты, без добора из каталога (у неактивного варианта каталог отдаёт фото соседа, 58614000). Нет фото в листинге —
пусто, в Check «need to upload» (84107000). Status остаётся как в отчёте листингов; Active без BUYABLE получает в
Check «Active, but Amazon doesn't sell it (not buyable)». Одинаковое главное фото у разных ASIN помечается в Check —
сравниваются ASIN, а не базовые коды: 59609000 (пила DRS-200BC без аккумулятора) и 59609000-1 (комплект с
аккумулятором и зарядкой) — один код, разные товары, одно фото 51JkaGT5QiL, и по коду пара не ловилась. Строки одного
ASIN (FBA и FBM) делят фото по делу. Снимок с владельцем, проверенным глазами, — в `PHOTO_OWNERS` ноутбука: у владельца
пометки нет, у остальных «Main photo is <модель> (<код>) — need to upload <своя модель> photo» (81RLT8zjlZL — JS-16C,
54477000; стоял главным у пускача JS-8 81123011). 71kz5G-7pEL — у шлангов 59327001 и 59327003 (общая пометка).

**Фото каталога (Catalog Items API) — не фото живой страницы, и выводов о странице выгрузка не делает** (решение
владельца 14.10.2026 вечером). До этого была колонка `Main image on Amazon page` и пометки в Check «на странице фото
другого товара» (46 строк) / «другое главное фото» (116): главное фото каталога сравнивалось с нашим по содержимому
(dHash 16×16, допуск 24 бита), а «чужим» считалось, если фото каталога совпадало с фото SKU с другим базовым кодом.
Проверка живых страниц это опровергла: у всех пяти активных SKU из списка 46 на странице тот же товар другим снимком —
наборы и коды одного товара (DHR-202BC: 54625000, 78059000, 99973000, 99974000, S3_59370000; триммер 30L: 99441000 и
48246000) делят одно фото. А 58614000 / B0F3DSKYJH на живой странице без входа переадресуется на покупаемого соседа
B0H66F7BS4 (SA i120) — это переадресация, а не фото каталога. Колонку и обе пометки убрали; сравнение осталось внутренним —
по нему добираются пустые слоты PT (только где главное фото каталога совпало с нашим).
